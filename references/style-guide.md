# 写作与排版风格指南

通用规范适用于任何预设；示例以官方预设 `embodied-ai-weekly` 标注。
所有阈值（字数、tags 数量、字段集合）以配置为准，本文只讲写法。

## 1. 骨架模板

```markdown
---
title: <按 title_template 生成，与 H1 逐字相同>
date: YYYY-MM-DD
description: <一句话导读，长度受 description.max_chars 约束>
tags:
  - <3–5 个主题词，受 tags.min/max 约束>
---

# <与 title 完全一致>

> <引用行：仅当 quote_line_template 非空时生成，日期必须与 frontmatter date 一致>

## <板块 1 标题（含 emoji，逐字匹配配置）>

::: card <type>
### 1. [标签] [标题](https://...)
- **<字段 1>：** ...
- **<字段 2>：** ...
:::

---

## <板块 2 标题>

> *<空板块占位行，逐字使用配置 placeholder>*
```

要点：

- 板块之间必须有 `---` 分隔线（`section_separator`）。
- 板块标题精确匹配配置（含 emoji 与空格），校验时做 NFC 规范化，但生成时应直接复制配置原文。
- 条目编号在**整个 issue 内连续递增**（跨板块不重新计数）。

## 2. 条目字段写法

- 字段名以配置 `entry.required_fields` 为准，顺序一致；别名（如"核心创新"→"核心亮点"）在转换时归一。
- 格式固定为 `- **字段名：** 内容`（全角冒号在粗体外）。
- 字段内容一段话写清，不嵌套列表；URL 放在 H3 标题里，字段内一般不再重复。

### embodied-ai-weekly 预设的三字段

| 字段 | 写什么 | 反例 |
|---|---|---|
| 核心亮点 | 该条目最关键的 1–2 个技术/产品事实 | 空泛形容："非常强大""值得关注" |
| 团队参考 | 站在读者工程团队视角的行动建议：能借鉴什么、注意什么坑 | 复述亮点、与读者无关的行业评论 |
| 载体 | `<形式> · N 分钟<速读/速览/精读>`，形式如 公众号文章/B 站视频/GitHub 仓库/论文 | 缺时长或形式含糊 |

## 3. 标题与标签

- H3 标题用原文标题（可轻微润色），必须带真实 URL；禁止编造链接。
- `[标签]` 是短分类词（如 论文、开源、教程、测评），词表保持收敛：优先复用历史期出现过的标签，
  新标签会触发 W05 提示，确有必要再引入。

## 4. 引用行与导读

- 引用行模板中的 `{date}` 用 frontmatter date 原值；`{topics}` 提炼 3–5 个本期关键词，用 ` / ` 连接。
- description 是站点列表页的一句话导读：写"本期有什么"，不写口号。

## 5. 正反例（embodied-ai-weekly 预设）

正例：

```markdown
::: card opensource
### 12. [开源] [LeRobot 新增双臂协同训练管线](https://github.com/huggingface/lerobot)
- **核心亮点：** 官方支持双臂 ALOHA 数据集格式，训练脚本内置协同动作分片。
- **团队参考：** 已有单臂管线可直接复用数据加载器；注意新格式与旧 checkpoint 不兼容，迁移前先跑通 eval。
- **载体：** GitHub 仓库 · 8 分钟速览
:::
```

反例（会被校验器拦截或降级）：

- `### 12. LeRobot 更新`（无标签、无链接 → E10）
- 字段名写"核心创新"未归一（→ E12）
- 载体写"GitHub"（无时长 → W03）
- card type 与板块不匹配（如论文板块用 `card opensource` → E09）

## 6. 中性默认（零配置）下的差异

- 无引用行、无 card 容器、`[标签]` 可选、字段仅 `摘要`。
- 写作要求同样适用：忠实原意、给行动建议、URL 真实。
