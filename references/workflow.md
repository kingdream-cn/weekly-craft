# 编刊工作流

已关联两库的周刊直接使用 [双仓库编刊](dual-repo.md)：prepare → 编辑 pool.md → build → 负责人审阅 → 按授权提交发布。保留既有台账与通知流程。

普通周刊可从已有草稿直接转换，不必补走搜集或素材池阶段：

1. 根据配置与最近一期组织 frontmatter、板块、三级标题、card 容器及条目字段；语义工作由 agent 完成。
2. 校验格式，查看跨期重复提示，生成 HTML 预览。可修改的警告供编辑判断，格式错误在发布前修正。
3. 负责人审阅实际内容，按当前明确授权提交、推送或创建 PR。详见 [发布说明](publishing.md)。

## 需要素材池时

```bash
python3 <skill目录>/scripts/new_pool.py --number 44 --from candidates.txt
# 编辑池内的 [x]、板块和字段
python3 <skill目录>/scripts/pool_to_issue.py sources/issue-44-pool.md
```

条目使用 `### [x] N. 标题` 和 `- 字段：内容`；字段与板块由预设决定。只有勾选项进入正文，编号在板块内自动重排。缺字段会保留缺口并报告，不由脚本生成事实。原文核对与摘要改写可按需参考 [风格指南](style-guide.md)。

## 恢复

根据产物内容与当前 Git 状态恢复，不仅凭文件存在就认定完成。双库 prepare 保留人工编辑并记录输入变化；build 从同一池重建生成文件，错误退出代表本次包尚不可用。

普通脚手架与素材池的覆盖参数以各脚本 `--help` 为准。发布失败后先核对目标分支、工作区和本地提交，保留已有工作，再按实际原因重试。真实通知交回现有运营系统。
